# Архив: скрипты первых этапов (разведка платы протеза)

Это скрипты первых этапов, сейчас они не нужны. Пока выяснялось, как управлять платой протеза
(STM32WB55 + SIM800C), они своё дело сделали; найденное перенесено в `../common/hand_link.py`.
Скрипты оставлены для истории и запускаются из этой папки: друг на друга они ссылаются внутри неё.

В проекте два независимых BLE-канала:
- **кисть (протез)** — BLE «INDY» `80:E1:26:09:2E:0B`, старый GATT-протокол Motorica (сервис fe40,
  характеристики fe42…fe57). Скрипты этого архива с пометкой «BLE» относятся к нему;
- **датчики** — HM-10 на плате TacMagVTOS (`BleLink` в `../common/sensor_link.py`). Этот канал
  рабочий, в архиве его нет.

Сейчас кистью управляют по UART (шина датчика ЭМГ) через `../common/hand_link.py`.

## Диагностика платы
| Файл | Что делает |
|---|---|
| `probe_board.py` | Только читает: список COM-портов, BLE-скан, дамп GATT (сервисы и характеристики), пассивное прослушивание UART. Через него нашли плату «INDY». |
| `gatt_80E126092E0B.json` | Результат `probe_board.py gatt`: полный дамп GATT кисти. |

## Кисть по BLE (старый протокол fe4x)
| Файл | Что делает |
|---|---|
| `indy_motion_test.py` | Первый тест движения: импульсы fe48/fe49 (выяснилось, что направления инвертированы) и запись телеметрии 2a37 в CSV (она так и не менялась). |
| `indy_cmd.py` | Разовые команды по BLE: открыть/закрыть N секунд, серия импульсов, стоп, запись fe42 (SHUTDOWN_CURRENT — порог тока, то есть сила хвата). |
| `force_staircase.py` | «Лестница силы»: несколько уровней fe42 подряд, на каждом длинное закрытие. Вызывает `indy_cmd.py`, этап показывает в `status_window.py`. |
| `force_sweep.py` | Замер силы для разных fe42, каждый раз из полностью открытого положения; результат вводится вручную в окне `status_window.py`. Отсюда вывод: шкала fe42 прямая, при 120–150 свободный ход обрывается. |
| `status_window.py`, `status.txt` | Окно поверх всех окон с крупным текстом текущего этапа для двух скриптов выше; текст читается из `status.txt`. |

## Разведка UART-шины датчика ЭМГ
| Файл | Что делает |
|---|---|
| `emg_emulator.py` | Притворяется датчиком 2EMG: отвечает на опрос версии `81 80 01 00` и логирует, что шлёт плата. Здесь же разбор пакетов (`parse_stream`, `describe`), его используют остальные скрипты ниже. |
| `emg_version_scan.py` | Перебирает номер версии в ответе на опрос, пока плата не начнёт обмен. Так нашли версию 6. |
| `emg_stream.py` | Шлёт поток ЭМГ `01 20 02 A B` по заданному профилю и параллельно читает BLE-телеметрию. Выяснилось: A=255 закрывает, B=255 открывает, пропорциональности нет. |
| `emg_gui.py` | То же вручную: два ползунка каналов ЭМГ, телеметрия BLE в реальном времени, кнопка СТОП по BLE. |
| `uart_test.py` | Проверка команд привода по UART (0x10/0x0F/0x12/0x11/0x13) и импульсов закрытия через ЭМГ. Отсюда протокол в `hand_link.py`: 0x10 открыть, 0x0F закрыть, 0x11 <pct> — закрыть с силой. |

## Датчики
| Файл | Что делает |
|---|---|
| `sensor_binary.py` | Разбор бинарных кадров платы датчиков 0xAA (давление пальцев), 0xAB (калибровка), 0xAC (оси по маске) и команды режимов. Прошивка сейчас их не шлёт (`Protocol_Send`/`Protocol_PollCommand` в main.c закомментированы), поэтому `raw_monitor` и `combined_gui` переведены на текстовую строку. Пригодится, если бинарный протокол вернут. |
